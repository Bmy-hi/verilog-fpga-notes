組合邏輯

#02 如何避免意外產生 Latch

💡 概念

組合邏輯的輸出應該只由當下的輸入決定。如果在 always @(*) 裡，某些條件下沒有指定輸出，代表那時候輸出要「保持原值」——這需要記憶元件，合成工具就會推出一顆 閂鎖器（latch）。

Latch 是 level-sensitive，容易造成時序分析困難與毛刺（glitch）問題，在 FPGA 上幾乎都是 bug。Vivado 會在合成報告出現 [Synth 8-327] inferring latch 警告。

🧩 程式碼

4 對 1 多工器（MUX），用「先給預設值」的寫法保證每條路徑都有指定：

module mux4 (
    input  wire [1:0] sel,
    input  wire [7:0] a, b, c, d,
    output reg  [7:0] y
);
    always @(*) begin
        y = 8'd0;          // 預設值：保證所有路徑都有指定
        case (sel)
            2'd0: y = a;
            2'd1: y = b;
            2'd2: y = c;
            2'd3: y = d;
            default: y = 8'd0;
        endcase
    end
endmodule

🔌 合成後的硬體

正確寫法只會合成出純組合的 MUX（在 FPGA 上用 LUT 實現），沒有任何記憶元件：

   a ──┐
   b ──┤ MUX ├──► y
   c ──┤ 4:1 │
   d ──┘  ▲
          sel

錯誤寫法則會在 MUX 後面多一顆 latch，y 在漏掉的條件下會「卡住」上一個值。

⚠️ 常見錯誤

1. if 沒有 else

always @(*) begin
    if (en) y = a;     // en=0 時 y 沒被指定 → latch
end
always @(*) begin
    if (en) y = a;
    else    y = 8'd0;
end

2. case 沒有涵蓋所有值也沒有 default

always @(*) begin
    case (sel)
        2'd0: y = a;
        2'd1: y = b;   // sel=2,3 → latch
    endcase
end
always @(*) begin
    case (sel)
        2'd0:    y = a;
        2'd1:    y = b;
        default: y = 8'd0;
    endcase
end

3. 多個輸出只指定了一部分：一個 always 裡有 y 和 z，某個分支只寫了 y，z 一樣會變 latch。解法同上——在 always 開頭把每一個輸出都給預設值。

✅ 重點整理

  • 組合 always 中「沒被指定」= 保持原值 = latch。
  • 最穩的寫法：always 開頭先給所有輸出預設值。
  • if 要有 else，case 要有 default。
  • 合成後一定要看報告有沒有 inferring latch 警告。
